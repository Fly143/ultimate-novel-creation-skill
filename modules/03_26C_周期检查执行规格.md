# 步骤5 周期性检查执行规格（03_26 附属·按需读取）

> **归属**：`modules/03_26_功能模块.md` 写后流水线步骤5 的完整规格，随瘦身拆出——仅**每5/10/50章**触发时读取，普通章不再常载。
> **接续位置**：步骤4.4 报告合并与 `.done_merge` 之后、`.done_chapter` 之前；周期章须待本规格全部通过才允许标 `.done_chapter`（03_26 步骤4.2 第6条与第七节清单同步约束）。


- 每5章：连贯性深度 + 质量深度（复用 D/F 深度模式，报告并入对应章节全量审核报告路径）。深度检查中发现 🔴 需修复项 → 阻断 `.done_chapter` 闭环（该章尚未标 chapter 标记），触发修复子代理（以全量审核报告为输入）；🟡 建议项不阻断
- 每5章：**约束量化检查**——主代理读取 `[书名]/记忆系统/约束/` 下三个追踪文件（金手指约束.md / 时间约束.md / 叙事线.md，由 22 强约束系统每章维护），按 03_24 三阶量化评分：
  - **金手指代劳率**：近 5 章金手指解决问题次数 vs 主角自身成长次数；比例 >2 标记 ⚠️（对照 22 金手指约束.md 的「最近5次使用」表）
  - **时间流逝感**：近 5 章故事内时间流速是否合理（章节数增长 vs 故事内天数）；200 章只过 3 天 / 3 章跳 10 年均标记 ⚠️（对照 22 时间约束.md）
  - **叙事线预期**：活跃支线超过 10 章未涉及、伏笔悬而未决超过 15 章 → 标记 ⚠️（对照 22 叙事线.md + 圣经/伏笔清单.md）
  - 结果追加到该章全量审核报告的「约束量化检查」节（只读 22 的数据做二次判断，**不写入** `约束/` 文件）
  - **⚠️ 的处置（★区别于正文修复）**：22/24 是叙事参谋，其风险是**跨章趋势问题**，改单章正文修不了，**不触发修复子代理**。同时**不阻断该章 `.done_chapter` 闭环**（否则"全部 PASS 才写下一章"的铁律会让趋势永远无法修正，形成死锁）。改为：
    1. ⚠️ 结果记入该章全量审核报告「约束量化检查」节 + 写持久标记 `[书名]/.done/第NNN章_constraint_warning.done`（状态位：趋势未修正）
    2. **下一章写作时**（03_06 步骤3），主代理检查该标记：存在 → P0 附上 `约束/` 三文件 + 全量审核报告「约束量化检查」节 ⚠️ 项，写作子代理针对性修正趋势（代劳率高 → 主角靠自己解决危机；时间流速异常 → 推进时间；支线被遗忘 → 切回支线）
    3. 后续章节自然修正 → 下次约束量化检查（每5章）回归正常 → 删除 `constraint_warning.done` 标记 → 趋势解除
  - 无 ⚠️ → PASS
  - 数据源 `约束/` 文件不存在时（22 尚未初始化）→ 跳过本项不阻断，报告注明 `Fallback: constraints unavailable`
- 每5章：跑 `foreshadow_timeline.py --project [书名]`（ps1 同口径）重生成 `圣经/伏笔时间线.md` → 主代理读「过期点名」节对照 圣经/伏笔清单.md 处置 ⚠️ 过期项；结果并入周期检查报告（派生件禁手改，见 00「伏笔时间线」节）
- 每10章：创新深度（**创新深度子代理**，见 03_14）+ 主代理阶段压缩 + **参数链压缩**（将最近 10 章的 参数链合并为 `[书名]/记忆系统/阶段/阶段N_参数.md`，格式见 03_24）；创新深度检查通过并写入 innovation.done 后，周期检查才算完成
- **周期检查完成条件**：需周期检查的章节须待步骤5 全部通过（10倍数章含 innovation.done）后，主代理才允许标 `.done_chapter`

**创新深度子代理调用规格（创新深度检查，返回完整报告）**：
> 完整调用规格见 `modules/03_14_功能模块.md`。以下为流水线适配摘要：
```
goal: 对小说作品执行创新深度检查，评估情节/人物/主题/设定四维度的创新性与原创度

context: 中文回复。项目目录：{工作目录}。
  ⚠️ mode: pipeline — 由03_26写后流水线步骤5调用。返回完整报告正文（不再仅返回PASS/FAIL一行）。
  需读取：{书名}/设定/{书名}_世界观设定.md、{书名}/设定/{书名}_人设卡.md、{书名}/设定/{书名}_情节大纲.md、
          {书名}/正文/第{NNN-9}章_*.txt ～ {书名}/正文/第NNN章_章节名.txt（最近10章正文）、
          {书名}/报告/创新深度检查报告.md（如已存在则覆盖）。
  检查维度：
  1. 情节创新：是否避免常见套路，是否有新颖性和意外性
  2. 人物创新：是否立体多面，成长是否自然，关系是否复杂
  3. 主题创新：是否有深度，价值观是否独特，是否有社会意义
  4. 设定创新：世界观是否独特，规则是否自洽，是否有创意
  每维度给出创新等级评分（1-10）+ 具体改进建议。

  报告写入：{书名}/报告/创新深度检查报告.md
  最后一行返回总结（三选一）：PASS / PASS（含优化建议）：[N]条 / FAIL: [N]个问题需修复
```

- 每50章：主代理卷压缩 + **参数链压缩**（将最近 5 个阶段参数表压缩为 `[书名]/记忆系统/卷/卷N_参数.md`）+ 复查高重要度伏笔近况
  - *非章节·分段模式：本周期**存在**，口径为"每50段"（与每50章同周期），产出文件名仍用 `卷N_参数.md`，仅作记忆回收粒度（段摘要/阶段压缩不足时兜底），不表示作品真分卷。注意：分段模式短篇（≤5万字，通常≤25段）**段数不足以到达该节点，实际不会触发**（即 03_26 分段模式说明的「无每50段周期检查」；周期本身存在，非"该周期不存在"）*
