# 功能模块 6：单章写作（子代理写作）
>
> **功能编号**：6
> **功能定位**：主代理纯调度——组装写作上下文后委托独立子代理完成章节创作。主代理只负责存文件+字数脚本校验，写作、审核、修复全部由子代理闭环。

---

## 一、核心特性

| 特性 | 说明 |
|------|------|
| **子代理写作** | 主代理读取记忆系统 → 组装写作 brief → delegate_task 委托独立子代理创作 |
| **四段式结构** | 子代理按开篇/铺垫/高潮/收尾结构创作 |
| **字数控制** | 子代理内控字数，主代理脚本校验；不达标→退回重写 |
| **记忆系统集成** | 写作子代理自行读取记忆文档（圣经/人物弧线/剧情时间线/伏笔清单/摘要/卷） |

---

## 二、执行流程

### 步骤0：写前预检（03_24）

> 确认 03_24 写前预检已完成。若未执行 → 先加载 `modules/03_24_功能模块.md` 完成预检再回到本步骤。

### 步骤1：主代理判定章节类型

主代理快速读取以下关键文件，判定本章类型（不组装全量上下文）：

1. 章节规划表中本章的「章节类型」「爽点类型」「出场角色」「场景」「冲突目标」
2. 伏笔清单.md 中状态为 🔄（准备回收）的伏笔

判定结果：

| 类型 | 特征 |
|------|------|
| 🔥 高潮章 | 爽点释放/大战/关键转折 |
| 📜 伏笔回收章 | 计划回收 ≥1 个远古伏笔 |
| 🌊 过渡章 | 日常/铺垫/支线展开 |
| 📦 标准章 | 常规推进（默认） |

### 步骤2：主代理读取字数配置 + 蓝图

1. 读取 `[书名]/设定/[书名]_立项定位单.md` 的「每章字数」字段 → 字下限=要求值，字上限=要求值+500
2. 未读到 → 默认 2000-2500
3. 同时检查 `故事圣经.md` 的「每章字数」字段作为备用。冲突时以立项定位单为准，自动纠正 圣经
   - *非章节·分段模式：本项目立项单用「每段字数/整篇字数」字段替代「每章字数」。**每段不硬卡 2000-2500**——每段字数按段落功能灵活（如 800-3000）。**整篇写完不卡字数**：整篇总字数距立项下限差不太多（≥下限的 85%）即视为达标，偏差更大才 🟡 提示（不阻断）；字数脚本仍按段跑，但下限判定以整篇计且带容差。段内过短（<400）或过长（>5000）仅 🟡 提示，不阻断*

### 步骤2.5：章节细纲展开 + 角色激活

**触发条件**：每章写作前必执行。此步骤将章节大纲展开为可写作的场景级细纲，并正式登记本卷预注册角色。

1. **规划表行检查（滚动兜底）**：先定位规划表第NNN章/段那一行，判定其是否可用：
   - **可用**：该行存在且含章级「内容概要」+「冲突目标」（非卷级梗概）
   - **缺失/退化**：该行不存在，或退化为卷级梗概（只有卷名/阶段描述，无章级内容概要与冲突目标）→ **主代理先调用 `modules/03_04_功能模块.md` 的「工作流E：续生成下一批章节」**补出本批（含第NNN章/段）章级规划，再继续本步骤后续展开。续生成完成后重新读取本章/段行。
     - *非章节·分段模式：本章/段行即"第NNN段行"，章节类型列按段落功能判定；触发工作流E时走分段模式（跳过卷、基于情节大纲续段）*
   - 续生成后仍缺失（如已超全书规划章/段数）→ 按 03_04 工作流E 第7步提示，并基于分卷大纲/情节大纲+当前进度临场规划本章/段（不阻断写作）。
2. 读取章节规划表中本章的「内容概要」「出场角色」「场景」「冲突目标」
2b. 读取分卷大纲中本卷的角色预登记信息（`[书名]/记忆系统/圣经/角色数据库.md`「按卷预设出场角色」表，由 03_04 步骤 6.2 预登记），同时读取 `[书名]/设定/[书名]_分卷大纲.md` 确认本卷核心冲突线和暗线推进节点
   - *非章节·分段模式：跳过本步的分卷大纲/按卷表读取（分段模式不生成分卷大纲、不填按卷表）；改为直接基于本章/段规划表的「出场角色」列 + 角色数据库.md 的「角色重要性层级」表推进角色激活（步骤4）*
3. 展开本章细纲（不写正文，仅做结构规划）：
   - 开篇钩子：[具体场景/动作/对白起手]
   - 铺垫段：[矛盾引入方式/压力递增节点]
   - 高潮段：[核心冲突爆发形式/爽点释放方式]
   - 收尾段：[余波处理/下章钩子]
4. 检查本章出场角色是否已在 角色数据库.md 正式登记：
   - 已登记 → 跳过
   - 在储备池但未正式登记 → 迁入 角色数据库.md 角色重要性层级表（主角级/核心配角/关键角色/次要配角/单元角色），补充本章首次出场信息
   - 完全不在任何表中 → 先入储备池再激活
5. 保存章节细纲：[书名]/设定/细纲/第NNN章_细纲.md

### 步骤3：主代理启动写作子代理

通过 `delegate_task` 启动写作子代理（`toolsets:["file"]`）。

**写作子代理需读取的文件清单**（主代理给出绝对路径，子代理自行读取，不嵌入 context）：

**P0 必读（所有章节）**：
- `[书名]/记忆系统/圣经/故事圣经.md` → 当前状态快照 + 上一阶段梗概
- `[书名]/记忆系统/圣经/人物弧线.md` → 全部角色的当前状态
- `[书名]/记忆系统/圣经/剧情时间线.md` → 最近 20 章事件因果链
- `[书名]/记忆系统/圣经/伏笔清单.md` → 全部活跃伏笔
- `[书名]/记忆系统/圣经/角色数据库.md` → 已出场角色基础信息
- `[书名]/设定/[书名]_章节规划表.md` → 本章的出场角色/场景/冲突目标
- `[书名]/设定/[书名]_文风设定.md` → **本书文风（03_01 生成，每章必读）**：句式/节奏/描写/对话风格指纹 + 体感锚点，写作子代理严格遵循
- `templates/单章结构模板.md`（skill 目录绝对路径）
- `references/高级写作技巧-整合版.md`（skill 目录绝对路径）→ **去AI化写作规则（每章必读）**：文字质量红线、反AI铁律、模板词黑名单、人味毛刺——动笔前对照，避免写出"AI 腔"
- **叙事趋势提示**：主代理在构造 P0 前检查 `[书名]/.done/` 下是否存在 `constraint_warning.done` 标记（由 03_26 步骤5 约束量化检查在 ⚠️ 时写入）——**存在** → 附上 `[书名]/记忆系统/约束/金手指约束.md`、`时间约束.md`、`叙事线.md` + 对应全量审核报告（`[书名]/报告/第{NNN-1}章_全量审核报告.md`）的「约束量化检查」节全文。**写作子代理必须读取该节，并把它给出的方向建议作为本章写作的行动约束**（代劳率高 → 安排主角靠自身成长解决危机；时间流速异常 → 明确推进故事内时间；支线被遗忘 → 切回该支线），在正文中体现修正，不得无视；**不存在** → 本条不加载。多个 ⚠️ 标记存在时全部附上

**P1 上下文（标准章+高潮章+伏笔回收章加载，过渡章仅最近3章）**：
- `[书名]/设定/细纲/第{NNN}章_细纲.md` → **本章细纲（步骤2.5 产出，写作必须遵循的四段式展开：开篇钩子/铺垫/高潮/收尾）**
- `[书名]/正文/第{N-2}章_*.txt` 和 `[书名]/正文/第{N-1}章_*.txt` → 前2章正文全文（确保语气、场景、对话风格衔接）
- `[书名]/记忆系统/摘要/第{NNN-5}～{NNN-1}章摘要.md` → 最近 5 章摘要
- `[书名]/记忆系统/卷/卷*.md` → 最近 5 个卷压缩（排除 模板.md；**第 50 章前卷压缩未生成时，改读 `[书名]/记忆系统/阶段/阶段*.md` 最近 2 个阶段压缩**）

**P2 按章节类型加配**：

**写作子代理 context 模板**：

```
goal: 创作小说《{书名}》第{N}章「{章节名}」

context: 中文创作。你是一位专业网文作家，需要创作第{N}章正文。

【章节信息】
- 章号：{N}
- 章名：{章节名}
- 字数范围：{字下限}-{字上限}字（中文汉字计数）
- 章节类型：{章节类型}（{类型说明}）
- 出场角色：{角色列表}
- 场景：{场景描述}
- 冲突目标：{冲突目标}

【写作要求】
1. 按四段式结构创作（**严格遵循本章细纲** `[书名]/设定/细纲/第{NNN}章_细纲.md`：开篇钩子/铺垫/高潮/收尾）：开篇(10-15%) → 铺垫(20-30%) → 高潮(40-50%) → 收尾(15-20%)
2. 参考单章结构模板（templates/单章结构模板.md）
3. 字数控制在 {字下限}-{字上限} 范围内
4. 风格：{风格描述/默认"与前面章节保持一致"}
5. **标点必须匹配写作语言**（写作语言 {写作语言}，默认中文）：正文使用该语言的标准标点规范，禁止混用或默认使用其他语言标点。中文正文细则——**禁止英文直引号 " "、英文逗号、英文句号、半角空格**；省略号用"……"（六个点不折行）、破折号用"——"（占两格）；引号用 “ ” 与 ‘ ’
6. 按必读文件中的去AI化写作规则（references/高级写作技巧-整合版.md）写作：避免模板句式、万用副词级联、AI高频词、情绪词点名、相邻同构
7. **检测器友好写作（★按第十四节「检测器友好改写」）**：写作时即避免——①总结性判断句（"这不是X，是Y"式，如"这灯烧的不是油。是命。"）改为动作/对话落地；②总分总段落模板（段落不要"主题句+展开+收束"），允许戛然而止/跳转；③刻意复杂度（不追求每句"词汇丰富+句法复杂"，允许平淡朴素直白的句子）。这三条是写前习惯，不伤害文笔
8. **叙事趋势修正**：若 P0 附有全量审核报告的「约束量化检查」节，**必须读取并按其方向建议落实**（代劳率高 → 本章安排主角靠自身成长解决危机；时间流速异常 → 本章明确推进故事内时间；支线被遗忘 → 本章切回该支线或给存在感），正文要能体现修正；该节不存在则跳过本条

【必读文件】（请按以下顺序读取，均为绝对路径）
{P0 文件列表}
{P1 文件列表}
{P2 加配文件列表（如有）}
{P3 参考资源列表（如有）}

【输出格式】
返回纯文本，第一行为章节标题，第二行起为正文。严禁元数据、Markdown 标记、作者旁白。

【字数内控】
写完后自行估算中文字数。如估算不达标（<{字下限}），在返回前自行扩写至达标。
```

**⚠️ 占位符替换**：主代理在调用 delegate_task 前，必须将上述模板中所有 `{...}` 占位符替换为实际值，文件路径使用绝对路径。

### 步骤4：主代理接收 → 保存 → 字数检查

1. 接收子代理返回的正文文本
2. 写入 `[书名]/正文/第{NNN}章_{章节名}.txt`（编号三位数补零，纯文本，严禁元数据/Markdown）
3. 执行字数脚本检查：
   ```
   python -c "import re,sys; t=open(sys.argv[1], encoding='utf-8').read(); print(len(re.findall(r'[\u4e00-\u9fff]', t)))" "[书名]/正文/第{NNN}章_{章节名}.txt"
   ```
4. 字数 < 字下限 → ❌ 退回重写。主代理将字数反馈传给同一写作子代理（重新 delegate_task，context 中包含"上一版字数不足，需扩写至{字下限}字以上"）
5. 字数 > 字上限 → ❌ 退回精简（同上）
6. 字下限 ≤ 字数 ≤ 字上限 → ✅ 合格

### 步骤5：移交写后流水线

字数通过后 → **立即加载 `modules/03_26_功能模块.md` 并执行其全部步骤（步骤0-6，从步骤1开始），不得跳过。**

> 03_06 自身不执行记忆系统维护、不标记任何 .done 文件、不生成摘要。全部由 03_26 负责。
> 03_24 写前预检仅覆盖部分就绪检查（含 故事圣经 存在性）；03_26 步骤0 的完整记忆系统就绪验证（5 圣经文档齐全）仍需执行。
> 详细的圣经更新字段与写法以 03_26 步骤2 为唯一权威定义。

## 四、批量写章节流程

逐章执行完整流水线，每章独立闭环：

```
for i in range(N):
    章节编号 = 当前章节 + i
    步骤0：写前预检
    步骤1：判定章节类型
    步骤2：读字数配置+蓝图
    步骤2.5：章节细纲展开 + 角色激活（必执行，不可跳过）
    步骤3：启动写作子代理
    步骤4：接收→保存→字数检查（不达标退回重写）
    步骤5：移交 03_26 写后流水线（审核+修复+记忆维护）
    → 确认本章通过后，再进入下一章
```

⚠️ **禁止一次性写完所有章节再统一审核。**

## 六、注意事项

1. **占位符必须替换**：步骤3 的 context 模板中所有 `{...}` 必须在调用 delegate_task 前替换为实际值
2. **文件路径用绝对路径**：子代理的独立上下文中相对路径不可靠，必须给出绝对路径
3. **字数检查不可跳过**：脚本校验，不依赖 LLM 计数
4. **退回重写要传反馈**：字数不达标时，重新 delegate_task 的 context 中须包含具体字数差距
5. **写作子代理只返回正文**：不要返回元数据、解释、分析
6. **03_06 不标记 .done**：所有 .done 标记由 03_26 统一管理
