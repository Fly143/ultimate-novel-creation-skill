# 全能小说作家

[![Version](https://img.shields.io/badge/version-9.6.0-blue)](https://github.com/Fly143/ultimate-novel-creation-skill)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

面向 AI Agent 的全流程长篇小说创作技能。从书名生成到千章完稿，配备三大自动系统（记忆系统/强约束/叙事质量管理）确保长篇连贯性。支持 AI 全自动和分步引导双模式。

## ⚠️ 使用前必读（先看这里）

本技能是**内容包**：加载后是否被严格执行，取决于宿主 agent 的 system prompt。**直接把仓库加载为技能就开写，agent 很可能会自由发挥、跳过流程，体验大打折扣。**请按以下三步使用：

1. **配置 system prompt**：将仓库根目录的 [system_prompt.md](system_prompt.md) 整段复制，配置为宿主软件的 system prompt（Claude Code / Cursor / API 接入 / Dify·Coze 等均适用，该文件顶部有各平台用法说明）
2. **加载技能**：将本仓库作为技能/上下文加载
3. **开始创作**：说「写小说」「继续」或任一触发词，技能会按场景路由引导

> 所有流程约束（强制执行协议、写后流水线、记忆系统维护等）都以技能文件为准；system prompt 只负责让宿主 agent 强制遵守它们。

### 🚀 写后流水线子代理（功能 26）

v9.6.0 写后流水线要点：

1. **朱雀「人工为主」**：验收目标为三态中「人工创作特征」**>**「疑似AI创作特征」；疑似≥人工时禁止宣称检测通过，进入人工证据强化轮。  
   - **写前**（03_06）：每章人工特征种子硬配额——感官锚点≥3、无用细节≥2、结构不完美≥2、低概率表达、对话毛刺（对话章）。  
   - **写后**（03_26 **4.1e 人工证据包**）：人工段注入≥2段/约≥300字 + 高疑似段整段重生 + 结构破坏 + 对话毛刺自查；**顺序 = U 后先跑 4.1b–4.1e 写 `.done_zhuque`，再修复**；禁止全文二次「降AI润色」/AI改AI；修复子代理不得整段重写人工注入段。  
2. **漏步硬门禁**：`.done_zhuque` 为章节闭环必需（无论 U 是否 PASS，步骤4.2/4.3 均须先跑 4.1b–4.1e 再标 chapter）。缺任一必需 `.done` → 禁止称完成、禁止写 N+1，自动补缺。  
   - 漏步矩阵覆盖：只交正文 / 跳U / 跳朱雀 / 跳圣经摘要 / 缺回执 / 未闭环写N+1 / delegate失败降级自审 / 半程收尾被当成完成。  
   - 「继续/下一章」前置闸门：先查上一章 `.done`，不齐先补缺。  
   - 每章结束必须输出【第NNN章状态】回执。  
   - **语义边界**：`.done_zhuque` 只表示 4.1e 步骤已登记，**≠** 朱雀「人工>疑似」已达标；闭环看 `.done`，达标看用户回传三态。  
   - **客观核验**：可选运行 `scripts/check-done.ps1` 或 `scripts/check-done.py`（按项目目录+章节号核验必需 `.done`；默认只认空标记，另对审核报告做「人工证据包」节软校验，可用 `-StrictReport`/`--strict-report` 提升为硬失败；不代替补跑）。

3. **双验收口径（必读，防把闭环当成过关）**：

   | 验收层 | 判定依据 | 谁说了算 | 全自动能否稳定达到 |
   |--------|----------|----------|--------------------|
   | **流水线闭环** | 必需 `.done` 齐（含 `zhuque`）+ 状态回执已输出 | skill / `check-done` 脚本 | 能（工具可验） |
   | **朱雀检测达标** | 用户回传三态中「人工创作特征」**>**「疑似AI创作特征」 | 腾讯朱雀 + 用户 | **不保证**——纯 AI 改写常停在「疑似」；要稳定过关通常需**真人重写关键句/高疑似段** |

   - 禁止：`.done_zhuque` 存在就宣称「检测已通过」。
   - 禁止：疑似 ≥ 人工时输出「已完成去AI化」。
   - 全自动模式的真实上限更接近「疑似」；「人工为主」是**目标验收**，不是流水线脚本能替你打勾的结果。强化轮与人工注入是提升概率，不是保证。

写后流水线包含 **1 个全量审核子代理 U**（v9.3 合并版，v9.5.6 扩为八项），每章写完**单次调用**即完成全部八项审查：

| 子代理 | 合并原项 | 职责 |
|:------:|:-----|:-----|
| **U 全量审核** | A 五道门禁 + B 强约束 + G 逻辑因果 + C 读者审稿 + F 质量 + D 连贯性 + E 节奏 + H 叙事规则 | 引用/一致性/蓝图/未知实体/描写 + 金手指叙事/时间约束/叙事线监控 + 空间/时间/因果/视角纯净 + 4维度评分 + 情节/人物/爽点/设定质量 + 人物/剧情/伏笔/世界观连贯 + 节奏诊断 + 能力因果/代价显性/空间连续/因果不可逆/资源约束（03_24 五维） |

> 八项检查在 U 内部按八节一次出报告；修复由独立子代理完成，保证审核与修复分离、避免自审偏见。

## 核心能力

- **28 个功能模块**：项目初始化 → 世界观 → 人物 → 大纲 → 单章写作 → 爽点/冲突/对话/打斗 → 节奏诊断 → 质量检查 → 强约束系统 → 作品拆解分析 → 叙事质量管理 → 读者审稿 → 写后流水线 → 导入已有小说 → 导出发布 → 轻量直出（短文/推文旁路）
- **五层自然语言记忆系统**：故事圣经 / 人物弧线 / 剧情时间线 / 伏笔清单 / 角色数据库，LLM 直读直写，不依赖外部工具
- **强约束系统**：金手指叙事约束 / 时间约束 / 多条叙事线监控，叙事参谋风格，不报违规只给建议
- **叙事质量管理框架**：写前预检 / 写后三阶复核 / YAML参数链条存档 / 可替换规则集，全流程叙事品控
- **正文纯净（v9.5.18）**：章节 `.txt` 只含标题行 + 正文，流水线全程不追加任何元数据——章级审计留痕与 YAML 参数链改存 `报告/第NNN章_章节档案.md`，正文可直接导入写作软件，导出/指纹/词频统计不再需要截断处理
- **千章级自适应上下文**：章节类型判定（高潮/伏笔回收/过渡/标准），自动调配加载深度，1000 章不爆上下文
- **章节规划表滚动生成**：首生成 min(30,全书) 章级规划，写前自动续下一批（或「扩展规划N章」手动控制），避免一次生成全书退化为卷梗概
- **卷数自适应**：按全书章数定卷边界（200万字≈10卷），不再写死50章/卷
- **短篇自动分段**：立项 ≤5万字 自动按"段"写作（跳分卷大纲）；也可显式指定「非章节·分段」
- **远古伏笔语境回读**：第 500 章回收第 1 章伏笔时，自动回读原始章节摘要保证语境完整
- **Bible 文档增长控制**：超 30KB 自动压缩远古内容，细节下沉到卷压缩，按需回读
- **五道生成门禁**：引用校验/一致性校验/蓝图出场校验/未知实体检测/描写一致性，不通过不视为完成
- **风格质量检查**：语言风格统一性/叙述视角一致性/文风成熟度（03_13，并入全量审核子代理 U 的 F 项）
- **13+3 个精选写作参考**：爽文理论、爽点设计、黄金开篇、风格技巧、打斗场景、高级写作技法、朱雀AIGC检测对策、真人指纹实测、规则集系统（通用默认+赛博-技术流，支持自定义）
- **15+3 个精选模板**：立项定位单、文风设定、世界观、人设卡、人物关系、情节大纲、章节规划、单章结构、章节档案（章级留痕+YAML参数链）、质量检查、朱雀去AI化检查清单、约束系统（金手指/时间/叙事线）等

## 快速开始

将本仓库作为 AI Agent 的技能加载。Agent 加载后自动读取 `SKILL.md` 及相关模块。

## 旧项目兼容（v9.5.18 正文纯净化的影响）

v9.5.18 起正文文件不再追加元数据块（章级档案改存 `报告/第NNN章_章节档案.md`）。**已有项目的旧章节无需改动**：

- 旧章节正文末尾的 `----` 元数据块 + YAML 参数链**继续有效，无需迁移**（仍留在旧章节正文末尾；v9.5.18 起新写的章节改为写在 `报告/第NNN章_章节档案.md`）
- 既有正文里的「完成步骤」字段已废除（完成状态一律以 `.done/` 空标记为准，见 03_26 第七节）；该字段可忽略，不影响任何流程
- 相关工具保留旧口径兼容：`scripts/fingerprint.byte.pl` / `wordfreq.byte.pl` 的 `--stop-at-dashes` 旗标仍可用于旧章节（按 `----` 行截断剔除元数据）

- 新旧章节可混存，互不影响；从新版起写的章节一律纯净
