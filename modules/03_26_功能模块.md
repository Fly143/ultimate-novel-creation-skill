# 功能模块 26：写后流水线（强制·每章必跑）
>
> **功能编号**：26
> **功能定位**：单章正文通过字数检查后，执行"主代理记忆维护 + 子代理审核 + 子代理修复"的完整闭环。
> **架构版本**：v9.5.6 — 在 v9.3（单全量审核子代理）基础上，将审核维度扩为 **1 个全量审核子代理 U**（A/B/G/C/F/D/E/H 全 8 项一次出报告，H 为 v9.5.6 新增的 03_24 叙事规则审查）。仍是 `delegate_task` 独立子代理，不降级为主代理自审（铁律不变）。修复子代理仍独立，保证"审核与修复分离"避免自审偏见。
> **铁律**：第 N 章全部 PASS + .done 标齐，**才允许写第 N+1 章**。黄金开篇"第1-3章"也必须逐章闭环，禁止连写再补审。

**执行逻辑**：

3. **任一缺失** → **直接终止**，提示用户执行功能18初始化记忆系统。记忆系统是写后流水线的硬性前提。

## 一、总流程（顺序不可跳）

```
1. 字数确认（复用 03_06 步骤4 脚本结果）→ 立即写入 `.done_wordcount`
2. 主代理更新 5 圣经 + 摘要 → 完成后写入 `.done_bible` + `.done_summary`
步骤3  单子代理 U（全量审核，合并 A/B/G/C/F/D/E/H 八项，一次调用）：
         读取全套文件 → 输出一份完整审核报告 → 末行三态总结
步骤4  收集结论 → 全 PASS 标 .done；有 FAIL → 独立修复子代理（只读 FAIL 报告+正文，不读记忆文档）
步骤5  周期检查（每5/10/50章触发）
步骤6  追加章节元数据
```

> **v9.3 架构变更说明**：
> - **3 审核子代理 → 1 全量审核子代理 U**：原 S1（A/B/G）、S2（C/F）、S3（D/E）合并为单个子代理 U，v9.5.6 起八项审查（+H 叙事规则）在一次调用内完成，输出一份报告。仍是独立 `delegate_task` 子代理，主代理不自审（铁律不变）。
> - **修复子代理保持独立**：审核（U）与修复由不同子代理完成，避免"自己查自己改"的自审偏见。
> - **B（强约束）仍始终 PASS**：并入 U 第二节，有风险时附加提示，零风险静默，不阻断流水线。
> - **审核子代理仍返回完整报告**：不再只返回 PASS/FAIL 一行。完整审核报告使得修复子代理可以直接读报告定位问题，无需重新加载全套记忆文档。
> - **修复子代理只读 FAIL 报告+正文**：不再需要读取记忆文档。审核报告已包含"具体段落引用→矛盾点→修改建议"，修复子代理按报告指示执行即可。
> - **.done 标记名全部保留兼容**：原 7 个审查标记（gates/约束/logic_causal/review/quality/coherence/rhythm）名称不变，由 U 在同一步一次性写入。

**U 全量审核子代理调用规格（合并 A/B/G/C/F/D/E/H 八项）**：

```
goal: 对第NNN章执行全量审核（合并原8子代理：五道门禁A + 强约束B + 逻辑因果G + 读者审稿C + 质量F + 连贯性D + 节奏E + 叙事规则H），输出一份完整审核报告

context: 中文回复。项目目录：{工作目录}，章节文件：{书名}/正文/第NNN章_章节名.txt。
  ⚠️ mode: pipeline — 由03_26写后流水线步骤3调用。返回完整报告正文（不再仅返回PASS/FAIL一行）。
  需读取文件清单（U 可自行用 file 工具读取）：
   - 章节正文：{书名}/正文/第NNN章_章节名.txt
   - 设定：{书名}/设定/{书名}_世界观设定.md、{书名}/设定/{书名}_人设卡.md、{书名}/设定/{书名}_情节大纲.md
   - 圣经：{书名}/记忆系统/圣经/故事圣经.md、人物弧线.md、剧情时间线.md、伏笔清单.md、角色数据库.md

   - 规则集（H 叙事规则用）：优先 `{书名}/设定/{书名}_规则集.md`（内容记录规则集路径），无此文件 → 直接读 `references/rulesets/通用默认.md`
   - 详细格式与维度定义（U 应读取以遵循规范）：
       B 强约束 → modules/03_22_功能模块.md
       C 读者审稿 → modules/03_25_功能模块.md
       F 质量 → modules/03_13_功能模块.md
       D 连贯性 → modules/03_17_功能模块.md
       E 节奏 → modules/03_12_功能模块.md
       H 叙事规则 → modules/03_24_功能模块.md（二阶五维审查）+ 规则集文件（见下）

  报告分八节，逐条检查，不重叠：

  【第一节 · 五道门禁 A】（逐条）
  1. 引用门禁：对话/叙述中引用的设定、事件、人物是否与已有文档一致
  2. 一致性门禁：人物言行是否与设定性格/当前状态一致（OOC检测）
  3. 蓝图门禁：本章是否偏离大纲规划（出场角色/场景/冲突目标）
  4. 未知实体门禁：是否出现未在设定文档中定义的新地名/组织/能力/物品（未注册实体）
  5. 描写门禁：环境/动作/外貌描写是否自洽、是否有明显感官矛盾

  【第二节 · 强约束 B】（始终PASS，仅提示）
  - 金手指叙事 / 时间约束 / 叙事线监控
  - 零风险 → 静默（报告中仅一句"强约束：PASS，无风险"）
  - 有风险 → 附加风险提示与建议（不阻断流水线）

  【第三节 · 逻辑因果 G】（7 项）
  【写手视角】
  1. 设定不自打架：本章呈现的设定是否与 圣经/世界观文档自我一致？（示例："灯长明"与"爷爷禁点"须区分，不可让读者误读为矛盾）
     ★ 设定分层判定规则（防误判）：
     - 前置预埋类（器物常态异象）：道具/异能的常态特征（特殊质感/温度/氛围），必须在高潮前分散预埋暗示；完全无铺垫 = FAIL；仅隐晦铺垫 = PASS（含优化建议）
     - 触发解锁类（激活后次生效果）：道具激活后才出现的衍生能力/代价（灯焰显形/疤痕异动/反噬），允许在高潮首次释放，不要求前置预埋，不算"设定空降"
  2. 信息越级：主角是否说了/想了本章尚未该知道的信息？（示例：第1章不知"灯油=阳寿"却写"抽的是他的寿"→越级）
  3. 角色认知自洽：角色基于已有信息得出的推论/判断，是否与角色自身已知事实矛盾？（示例：亲眼看到人搬进去，却心想"付了租金不住"→认知矛盾）
     ★ 本能行为判定参考（不做强制校验，仅作审稿提醒）：
     - 区分「主动理智抉择」与「绝境本能应激动作」
     - 本能动作若存在童年记忆/感官特质/身体反应等前置线索，不可直接判定为动机断层
     - 仅「无任何前置痕迹的突然反常行为」才可判定为 FAIL；有铺垫但渲染不足 → PASS（含优化建议）

   ★ 配角立体度判定：
   - 按角色类型区分，不按章节号区分：
     · 一次性工具配角（单章出场、仅承担信息传递/背景交代）：允许轻量化，不强制个性细节 → PASS / PASS（含优化建议）
     · 长线出场配角（跨≥3章或设定为常驻/半常驻）：如无专属特征/记忆点 → FAIL
     · 回忆人物（祖辈/已故等）：首现留白制造悬念属合理写法，不扣分；长线未补全 → PASS（含优化建议）

  【读者盲读视角】
  4. 空间矛盾：物体/人物/声音位置是否明确且不矛盾（如灯在主角屋，却写"听见哭声从灯方向来"）
  5. 时间矛盾：跨度/顺序是否合理，有无同时出现在两处
  6. 因果断层：关键情节因→果是否成立，有无机械降神/凭空能力或信息
  7. 视角纯净：有无作者跳视角旁白（主角无此认知的系统/档案/上帝句）

  【第四节 · 读者审稿 C】4 维度评分（连贯/吸引/爽点/bug），按 03_25 格式输出
  【第五节 · 章节质量 F】情节/人物/爽点/设定质量检查，按 03_13 格式输出
  【第六节 · 连贯性 D】人物/剧情/伏笔/世界观跨章连贯，按 03_17 格式输出（读前10章摘要）
  【第七节 · 节奏 E】本章及近程节奏诊断+优化建议，按 03_12 格式输出

  【第八节 · 叙事规则审查 H】
  - 规则集选择：优先读 `{书名}/设定/{书名}_规则集.md`（用户通过功能24 `规则集`/`加载规则集` 选定后生成）；不存在 → 用 `references/rulesets/通用默认.md`
  - 按所选规则集的五维定义逐条审查本章（每维 ✅/❌ + 段落引用 + 修改建议）：
    1. 能力因果法则：力量/能力的使用是否遵循完整逻辑链（动机→判断→行动→结果），有无空降解围/无铺垫能力空降
    2. 代价显性法则：每次使用能力是否支付了可感知代价，代价描写是否与能力级别匹配（按规则集代价表）
    3. 空间连续法则：跨区域移动是否有合理耗时（按规则集耗时基准，短/中/长/跨世界分档）
    4. 因果不可逆法则：死亡/关键损毁/身份暴露/关系变化等是否被不合理翻转（死亡绝对不可逆；恢复需世界规则允许+对等代价）
    5. 资源约束追踪：资源消耗是否与剧情匹配，有无资源无端恢复/超规格使用（按规则集资源池字段）
  - 与第三节 G 的互斥边界：G 管"本章内部逻辑自洽"（信息越级/认知矛盾/因果断层），H 管"叙事规则维度的量化约束"（能力代价/空间耗时/资源账本）——同一段落触犯多项时按最严格标准独立判定

  互斥边界：
  -「信息越级」专指主角已知信息的前后一致性
  -「角色认知自洽」专指角色基于已有认知的推理是否自相矛盾
  -「因果断层」专指剧情事件因→果链断裂
  - 同一段落触犯多项时，按最严格标准每项独立判定 FAIL

  每节每条输出格式：
  ✅ 或 ❌ + 具体段落引用 + 矛盾点说明 + 修改建议（含预期正确写法）

  报告写入：{书名}/报告/第NNN章_全量审核报告.md
  最后一行返回总结（三选一）：
  - PASS（八节全✅，无任何问题）
  - PASS（含优化建议）：[N]条建议（有可优化点但非逻辑硬伤，不触发修复）
  - FAIL: [N]个问题需修复（存在逻辑硬伤，必须触发修复子代理）
```

> **摘要数量差异设计说明**：U 一次性读取前 10 章摘要，覆盖 C（读者体验，中等上下文）、D/E（跨章连贯与节奏，长程上下文）的不同需求——D/E 需要更长近期上下文，C 侧重本章自身体验，二者在 U 内部按节分别处理，摘要数量差异是有意为之。

## 三、步骤4 结论收集与修复

### 4.1 结论收集与分类

等待步骤3 全量子代理 U 返回（单一结论，含八节）。

- ⚠️ **第二节 B（强约束）始终 PASS**：不触发修复，不阻断流水线。
- 按三态分类：

| 状态 | 含义 | 操作 |
|------|------|------|
| `PASS` | 无任何问题 | 标全部对应 .done |
| `PASS（含优化建议）：[N]条` | 有可优化点但非逻辑硬伤（如词汇重复、氛围渲染不足、配角单薄等） | **触发修复子代理按建议优化**（改最少原则）→ 二次审核无新 FAIL → 标全部对应 .done |
| `FAIL: [N]个问题` | 存在逻辑硬伤（因果断裂/设定矛盾/OOC等） | **触发修复子代理**（❌ FAIL + 🟡 建议全量处理） |

### 4.1b 分布统计（客观指标）

U 返回后，主代理运行**分布统计脚本**，把客观指标追加到审核报告「分布检查」节（修复子代理据此改分布）：

- 命令（按宿主可用性**依次尝试**，任一成功即可；脚本为四实现同口径，输出一致）：
  1. `python scripts/fingerprint.py "{书名}/正文/第NNN章_章节名.txt"`（最通用：Windows/macOS/Linux 通常都带 python）
  2. `perl scripts/fingerprint.pl "{书名}/正文/第NNN章_章节名.txt"`（macOS/Linux 自带 perl；若报 `Can't locate Encode.pm` / `Unknown PerlIO layer` 等错误 → 宿主是缺 Encode/PerlIO 的精简 perl，改跑第 3 项）
  3. `perl scripts/fingerprint.byte.pl "{书名}/正文/第NNN章_章节名.txt"`（纯字节级零依赖版，不 use utf8、不用 :encoding，任何精简 perl 5 都能跑；章节文件带标题行/`----`元数据时加 `--skip-first` / `--stop-at-dashes`）
  4. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/fingerprint.ps1 -Path "{书名}/正文/第NNN章_章节名.txt"`（仅 Windows/装了 pwsh 的宿主）
  
  脚本输出句长均值/中位/≤12占比/≤20占比/方差、段长均值/≤50占比、对话占比、每千字 的/！/？/……
- **判定**：对照 `references/高级写作技巧-整合版.md`「真人网文统计指纹」区间（设定了文风的书对照 `[书名]_文风设定.md` 的文风指纹）——句长方差过小、≤20 字占比明显偏低、段落等长、对话占比异常、修饰密度过高，任一明显偏离且趋于"规整" → 审核报告标记 🔴 分布未达标（需改分布）。

- **容错缓冲带（防边缘值反复改）**：真人区间本身极宽（方差110-1536、≤20字17-62%、≤12字7-41%），且文体差异巨大（轻小说/搞笑流方差实测低至110、≤20字占比低至17%）。**禁止卡死边界**：
  - 方差 **≥ 90 即视为基本达标**，仅当方差 **< 90 且整章形态明显规整**（长句主导、几乎无短句/碎片，像"通篇中长句等距"）才标 🔴；方差落在 **90-110 边缘 → 标 🟡 提示**（不阻断、不强制打散）。**碎句过多型**（短句连篇、方差反而很低）属另一极端，不在此 🔴 范畴，按防过度规则处理，不强制拉长短句。
  - ≤20字/≤12字占比同理：落入区间、或仅差 1-2 个百分点（如 ≤20字占15% vs 区间17%）→ 🟡 提示，不标 🔴。
  - 设定了文风指纹的书以该书文风区间为准（如忘语式冷静长句流短句少属正常，绝不因"短句少"判 🔴）。
- 修复子代理将「分布检查」节数值作为反AI腔改味的输入；**修复后主代理重跑上述脚本（任一可用实现）对比——落入真人区间、或落入上文「容错缓冲带」（方差≥90、占比仅差1-2个百分点）即视为通过，不再强制机械打散**；仅在方差 < 90 且形态明显规整、或占比严重偏离时才判未修干净
- **⚠️ 防过度**：拉大方差靠**长短自然交替**（长句内部加逗号节奏、关键处用短句强调），**禁止把长句机械切成碎片凑方差**；修复后通读改动段落，若有"碎句堆砌/一句一段/读起来断断续续"感 → 优先回退为长句微调而非继续切短。分布区间是"像不像人"的参考，**不是牺牲通顺的硬指标**——通顺与方差冲突时，通顺优先，报告注明 `note: distribution relaxed for readability`
- 全部实现均不可用（宿主无 python/perl/pwsh）→ 降级为 U 质量节的主观目测，报告注明 `Fallback: fingerprint unavailable -> LLM estimation`

### 4.1c 用词检查（AI味词密度）

分布达标后仍被判"疑似"，多半卡在用词层。主代理运行**词频统计脚本**，把 AI 味词密度追加到审核报告「用词检查」节：

- 命令：`perl scripts/wordfreq.byte.pl "{书名}/正文/第NNN章_章节名.txt"`（纯字节级零依赖版，任何 perl 5 都能跑；带标题行/`----`元数据时加 `--skip-first` / `--stop-at-dashes`）
- 脚本按 `references/高级写作技巧-整合版.md` 铁律三分档输出每类词每千字频次，**超档线标 ❌**：
  - 高危类（单章≤0.5/千字）：然而、不禁、瞬间、宛如、犹如、仿佛
  - 中频类（单章≤1.5/千字）：微微、淡淡、轻轻、缓缓、默默、悄悄、心中、眼中、脸上、似乎、不由
  - 正常类：突然、马上、一下、一些（不检查）
- 脚本同时输出**连环堆叠句密度**（每万字堆叠句数）：
  - 判定阈值：>10 句/万字 → 🔴 堆叠超标；1-10 → 🟡 注意；<1 → 正常
- **判定**：任一 ❌（或堆叠 🔴）→ 审核报告「用词检查」节列出超标词与频次 → 🔴 用词未达标（修复子代理按铁律三分档替换/删减，优先处理高危类）
- **⚠️ 防过度**：超频词**优先用具体动作/物件/对话替换**（如"微微一愣"→"脚步顿住"，"心中一动"→具体反应），替换方向见 `references/高级写作技巧-整合版.md` 铁律三附表「人味词」；**禁止机械删除**让句子变干瘪；删掉读不通就换表达，不硬删。铁律三分档的"≤1处/≤8处"是**上限不是目标**——不要求每章刻意凑满，也不为达标而删掉本来自然的那 1-2 处
- **写前联动**：写作时（03_06）已按铁律三分档限流（高危单章≤1处、中频合计≤8处、禁止连环堆叠）；本步是写后兜底，防漏网
- 无 perl 环境 → 降级为主观目测，报告注明 `Fallback: wordfreq unavailable -> LLM estimation`

### 4.3 修复路径（任一 FAIL 或含建议项触发）

U 返回 `FAIL` **或** `PASS（含优化建议）` → 启动**独立修复子代理**（处理 ❌ FAIL 项 + 🟡 建议项，全量修改所有标记）：

**修复子代理调用规格**：

```

  1. {书名}/正文/第NNN章_章节名.txt — 待修复的章节正文
```
