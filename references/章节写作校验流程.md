# 章节写作校验流程（03_06 步骤4 执行细节）

> 适用范围：字数校验、人工种子核对、段落长度校验、规划表场景核对。
> 写入时机：03_06 步骤4 主代理接收子代理正文后、移交写后流水线前。

## 一、字数校验（步骤4.3）

脚本：`python -c "import re,sys; t=open(sys.argv[1], encoding='utf-8').read(); print(len(re.findall(r'[\u4e00-\u9fff]', t)))" [正文文件]`

- 低于字下限 → 退回子代理扩写（context 中包含"上一版字数不足，需扩写至{字下限}字以上"）
- 高于字上限 → 退回子代理精简
- 在范围内 → 通过

## 二、人工种子核对（步骤4.7）

按写作要求第8条硬配额逐项通读正文：

| 配额 | 基准（2000-2500字章） | 检查方法 |
|------|---------------------|----------|
| 感官锚点 | ≥3处 | 找气味/触感/声音/环境噪音的具体描写 |
| 无用细节 | ≥2处 | 找不承担推进功能的闲笔/物件 |
| 结构不完美 | ≥2处 | 跳时间/少过渡/未解释信息残留 |
| 低概率表达 | 每500字≥1处 | 非常规比喻或冷门形容 |
| 对话毛刺 | 对话章 | 口癖/打断/半句/夹动作 |

不达标 → 退回子代理**定点补种**（指明缺哪类、建议位置），**禁止**借机全文重写。

## 三、段落长度校验（步骤4.7b·文风硬约束）

**触发条件**：项目文风设定「每段上限句数」字段有具体数值（>0）。

**检查方法**：

```python
import re

# 从文风设定读取上限（示例：文风设定文件路径已知）
with open('[书名]/设定/[书名]_文风设定.md', encoding='utf-8') as f:
    text = f.read()
# 提取「每段上限句数：N」
m = re.search(r'每段上限句数[：:]\s*(\d+)', text)
limit = int(m.group(1)) if m else 0

if limit <= 0:
    print('文风设定未设置每段上限，跳过段落长度校验。')
else:
    paragraphs = [p.strip() for p in content.split('\n') if p.strip()]
    for i, p in enumerate(paragraphs):
        sentences = re.findall(r'[。！？]', p)
        if len(sentences) > limit:
            # 标记为需拆段
            print(f"段落{i+1}: {len(sentences)}句（上限{limit}）— {p[:60]}")
```

**修复方式**：主代理**当场拆段**，不退回子代理。在动作/对话节拍处断开换行。

**拆段原则**：
- 在说话人动作/神态处断开（"刘波说"前或后）
- 在场景切换处断开
- 保留对话完整性（不在引号中间断开）
  - 全引号对白段（断行即短句）最易把句堆过上限：嵌入/插入人工证据段后逐段点句数，超限优先**按说话人动作拆成两段**，不删对白凑句数
- 拆完检查：每段仍 ≥1 句，总字数变化 ≤5%，且重跑「每段句数」与「对话占比」两处口径

**修复后**：重跑字数脚本确认字数未缩水。

### 3.5 量尺口径统一（所有「≤N字 / ≤N句 / ≥N%」判读共用）

- **排版硬约束去标点再量**：「单句 ≤N 字」「每段 ≤N 句」等约束，句长用 `re.sub(r'[，。！？、；：“”‘’（）——……·]', '', s)` 后的字符数计——**不得把原文标点计入**，否则含引号/破折号的句子会被误判超标。
- **句数按句末符号（`。！？……`）切分后滤空片段**，不按行 split、也不把紧邻折行当句界；段界一律以**空行块**为准（行口径 ≠ 空行块口径，二者不得混用）。
- **口径脚注**：报告凡报「方差/字数/占比」必须写明是哪个脚本、哪个口径（汉字口径 / UTF-16 单元含标点口径 / 含标点字符口径；对话占比是「引号内汉字÷全文汉字」还是「引号内字符÷全文字符」）。同一份文档不得混用两种口径；口径冲突时先做「让位裁量」并登记（各口径读数＋取舍理由＋遗留到哪一章收敛），写入细纲 CONTEXT 与 U 报告。
- **新脚本先冒烟、读数只信脚本**：新写的度量脚本先在一份已知输入上与已验证脚本（`scripts/fingerprint.py`/`text_guard.py`）逐字段对拍一遍，内联片段先 `print()` 断言一个已知值再拿去跑正文；子代理自报读数与主代理离线复测不一致时**以脚本为准**，并在报告登记差异，不得照抄自报当证据。

## 四、规划表场景核对（步骤4.7c）

**检查方法**：

1. 读取 `记忆系统/上下文.md` 的「下一章承诺」字段
2. 读取章节规划表本章行的「场景」列
3. 两者不一致时 → **以上下文承诺为准**

**理由**：上下文是派生件（由 state 渲染），规划表可能是上一轮规划时写的旧值，未随后续修订更新。

**处置**：在细纲 CONTEXT 中注明“场景取值：上下文承诺为XX，规划表为YY，以上下文为准”。

---

**时间列同检与 U 预列（规划表核对的两个补充项，同批执行）**：**时间列同检**：再核规划表「时间/天数」列与 `记忆系统/上下文.md`「当前位置」的天数口径——规划表时间常停在早期口径（已观测第17行标「第8天」，实际按上一闭环章第10天的次日＝第11天）；不一致时以上下文卡/上一章章首锚点口径为准，并在细纲 CONTEXT 写一行「实际天数＝X（依据：第N章章首锚点）」，避免章与章天数跳。 **替 U 预列「已登记未兑现」判定项**：派发全量审核 U 时，把台账里已登记但正文未兑现的项逐条写成显式判定项放进 U 的 context（伏笔台账 `planned_resolve_ch` 与正文的差异、规划表旧条与执行路线的脱节、事实台账里已记载的疑点），要求 U 对每一项给 ✅/❌ + 段落号 + 修复方向；同时声明这些已登记的历史脱节**不算本章新增缺陷**——U 只按规则扫描会漏判「规则↔台账之间的裂缝」，或把它重复报成本章新问题。


## 五、句长方差交付门禁（步骤4.7d·移交流水线前必检）

> 口径与 4.1b 容错带同源：方差 ≥110 达标；90–110 容错带；<90 未达标。先落盘再移交，避免到 4.1b 才打回头。

**检查**（与字数脚本同批执行）：先用 `python scripts/fingerprint.py <正文.txt>` 取方差／分布（本脚本只收**单个正文路径**，多余参数即报错退出——`--skip-first`/`--stop-at-dashes` 是 `scripts/wordfreq.byte.pl` 的开关，不是 fingerprint 的）；正文末尾带 `----` 元数据块时先截到 `----` 存临时文件再喂 fingerprint，或改用 `perl scripts/wordfreq.byte.pl <文件> --skip-first --stop-at-dashes`。

**口径纪律（判方差只认一个脚本）**：下方内联脚本按「汉字数」算句长，`fingerprint.py` 按「UTF-16 单元（含标点）」算——同章两种口径方差会差出几十点，不得混用、不得跨脚本对齐容错带；判 `≥110/90–110/<90` 只用其中一个口径（默认 fingerprint），报告标注脚本名。同段同理：`fingerprint.py` 的「段落数」是**行**口径（`splitlines`），与 check-done 证据节「按空行分块」的段号不是一回事——证据节段号必须用空行块口径，别拿 fingerprint 的「段落数」当段号上限或交叉校验依据。

```python
import re, statistics
glass = [s.strip() for s in re.split(r'(?<=[。！？……])', content) if s.strip()]
lens = [len(re.findall(r'[一-鿿]', s)) or 1 for s in glass]
print('方差', statistics.pvariance(lens), '句数', len(lens))
```

**项目文风优先（句长禁忌的让位判定）**：

1. 先读 `[书名]/设定/[书名]_文风设定.md` 的句长上限（如「禁止超过 N 字的句子」/「平均句长 A–B 字」）。**有上限且与 40–60 字长句穿插冲突时 → 本节长句穿插不适用**，走第 2、3 条。
2. 改用「超短句（4–9 字）↔ 中长句（上限内）自然交错」拉开句长方差，配合合并碎片段；**禁机械切碎长句凑方差，禁超出项目句长上限**。
3. 修前先跑 `scripts/fingerprint.py` 取**本书章族谱系**（既往 2–3 章：段落数/句子数/段长均值/句长均值/句长方差）作基线；修后「落回族系区间」才算修好，不以单章数字为唯一目标。
4. 停落在容错带（方差 <90 但整章短句主导、形态不像电报体）→ 标 🟡、不阻断，报告加 `note: distribution relaxed for readability (book style caps sentence length)`，照常移交流水线。
5. **先算算数再判不可达**：判方差目标前按章句数 n 与句均算出「达标需多少句、每句多长」；若所需句型（40–60 字）与项目硬禁忌（单句 ≤30 字）互斥 → 结构性冲突：记让位说明（让了什么＝哪条指标、代价＝什么、依据＝哪条用户/项目硬约束优先级更高）后**停止**反复修补，改走第 2 条。
6. **族谱先辨成因**：往章高方差若来自超限长句（违反本禁忌的先例），不把它当达标参照，一律按禁忌从严（让位说明照记）；只有往章同样严守字数上限而方差仍高，才可把「与自家族谱一致」当作达标判据。

**重复残留快扫（移交流水线前必做，正文来自任何来源都要扫）**：子代理成品稿、自动合并产物可能携带重复小句（同段内同款描述连写、相邻段共用起句）——字数与段落脚本只查缩水不查膨胀，重复块能蒙混过关。

- 段内：对每段做 N 字窗口（N=4–8）重复扫描，同段出现 ≥2 次即列候选（排除人称/虚词打头的窗口，如「他/她/这/那/了/的/一/就/是」）。
- 相邻：相邻两段共现的 ≥4 字连续窗口列候选（跨段重复常以换行分隔，只看段内会漏）。
- 候选逐条判读后修：删重复小句或与相邻句合并为一处；每处替换前断言 `content.count(old)==1`，修完重跑字数脚本 + `scripts/fingerprint.py` 确认未膨胀。
- 与本文件下方「修复替换防重复」的分工：本条抓**已存正文的存量残留**，那条防**替换操作引入的复制重复**——两条都要跑。

**判定与处置**：
- 方差 ≥110 → 通过

**操作前探测（防「脚本显示完成但零命中」的静默空跑）**：

- 动手前先 `open(path,'rb').read()` 探测行尾符（`\r\n` 还是 `\n`）与段落分隔（空行还是紧邻），脚本的 split 口径必须对齐——行尾不符时全文被当 1 行、合并/替换静默 0 命中（已观测：按 CRLF 处理但文件是 LF，几轮结构调整全部空跑，重扫才发现）。
- 合并/替换前全量预检命中数并 fail-fast：命中数 = 0 的批次立即停下排查，禁止「跑一遍但零改动」当作完成。
- 合并的结果必须写回「最近一段非空段落」的槽位；写进取空行/空段槽位会造成内容重复（字数脚本只查缩水不查膨胀——已观测合并后正文出现整段重复，`count==1` 断言未用）。
- 章内对白段与叙述段交替，相邻叙述段之间隔着对白 → 只合并「两端均无引号、各自 ≤16 字」的段，禁止跨对白边界/引号闭合处合并（会打断说话句子、引号配对错位）。
- 预算记实：方差贡献 ≈ (新句长−句均)²÷句数；句数 >320 且句均 ≤8 字的首版，字数配额内拉长句可能够不到 110——停在 90–110 容错带并如实记录，优先保短句占比/感官锚点/禁用词达标；3 轮仍 <90 → 移交流水线并在回执注明。

- 90–110 → 记 🟡，不阻断，正常移交（交 4.1b 同口径复算）
- **方差 <90（电报体）→ 当场「句法修复轮」（主代理机械操作，不退回子代理）**：
  1. 穿插长句：叙述/环境段、对话标签后、内心活动段插入 15–25 字细节句或 40–60 字插叙句（感官/物件/拖延动作），每 150 字左右 1 处（2400 字章约 16 处）
  2. 合并碎片段：1–2 句的独立短段并入相邻段（动作段/对话段）
  3. 唯一命中断言：每处替换前 `content.count(old)==1`，替换后核对新短语唯一出现（防静默复制重复块——字数/段落脚本不查膨胀）
  4. 修完重算方差；字数超上限则删冗余（**禁为控字数删长句**）
- 一轮后仍 <90 → 再加长句 5 处重算，最多 3 轮；仍不达标 → 移交写后流水线并在回执注明该情况
- **防回落**：流水线内凡删除长短句/增删长句的改动（含 U 意见修复、证据包增删）→ 改完重算方差，跌破 90 立即补 1–2 处 40–60 字动作/细节长句再重算；删除一处长句与新增一处短句会相互抵消方差收益，删除类改动必须补长句
- **源头预防**：写作子代理 context 加一句「长短句交错、避免通篇短句/电报体」指令

**修复替换防重复**：主代理对已存正文做 in-place 字符串替换（采纳审核建议、补过渡句、拆段、改引号）时，若替换的新文本与原文已有内容重叠，会静默复制出重复段/句——字数与段落脚本只查缩水不查膨胀，重复块能蒙混过关。每次替换后核对旧块已消失、关键短语出现次数符合预期（如 `content.count('陈默没接话')` 应为 1）；重复即当场删冗，再重跑字数脚本。**段级并段/切片重建同属本体类风险，必须三验**（把 N 段并进 1 段、或把 1 段拆成 N 段）：①落盘前按「原块数 ± 净增」核算目标块数，对不齐不写；②>5 字的重复段体整段去重扫描（比小窗口扫描可靠，小窗口会漏同款长段）；③替换前断言 `count(old)==1`、替换后断言新块出现次数符合预期。成因：切片表达式若把被替换块的原位与新生块都留着，正文就出现**整对**重复段，字数/段落脚本读不出来。**patch 失配先验行尾符再照字节拼串（正文常为 CRLF）**：`patch` 多行匹配不识别 CRLF——正文行尾为 `\r\n` 时整段失配。处置优先级：①先定位后 `repr(open(path,'rb').read()[i:i+80])` 看是否 `\r\n`；②改用 `execute_code` Python `open(path, encoding='utf-8', newline='')` 做含 `\r\n` 的 `count==1` 替换；③拼 `old_string` **一律从字节原文照录，勿凭记忆重敲**（已观测把『来回数过』敲成『来数过』导致重复替换；另注意同义不同字：『来回』vs『来』，漏一个字就失配）。

**wordfreq 调用形态与字数口径补充**：wordfreq 是 **Perl** 脚本——`perl scripts/wordfreq.byte.pl <正文> --skip-first`；用 `python` 跑 `.pl` 会抛 Python 解释错误而非运行结果，易误判脚本损坏。`fingerprint.py` 的「总字数」字段＝含标点口径，验收计数按**汉字口径**（对齐 `_state.json` `wordcounts`，见 `modules/03_06_功能模块.md` 步骤4「子代理回传验证」⑤）。

## 六、设定文档标点自检（写作子代理注入前）

- 细纲/规划表/档案/约束文档的引号、破折号同样全角（标点红线适用于全部项目文档，不限于正文）
- 细纲写完 → 半角直引号成对替换为 “ ”（代码与正文「标点后处理」同套），复核 `content.count('"')==0` 再注入写作子代理（半角引号源头之一是子代理照搬细纲直引号）
- 正文保存前的半角引号检查按本节下方「标点后处理」执行（含替换后重扫与弯引号方向配对）
- 脚本拼接产出的中文文本（U 报告、章节档案、证据节、任何子脚本产物）落盘后同样扫半角标点与**繁体残留**：字面量里的半角引号会一路带进成品报告；繁体字面量会让证据节锚点/样例匹配失效。归一化或替换后重跑内容校验再交付。

**标点后处理（半角引号·保存后必检）**：写作子代理可能不可靠地遵守格式规则（已观测：上下文模板要求全角引号，子代理仍返回上百个半角 `"`）。保存正文后立即检测半角引号，存在即按出现顺序成对替换为全角 “ ”（奇数个时最后一个也转全角）。主代理自身新增的过渡句/补充内容也须用全角引号——后处理捕获所有来源。Python 一行修复：
```
content = open(path, encoding='utf-8').read()
if '"' in content:
    out, open_q = [], True
    for ch in content:
        if ch == '"': out.append('\u201c' if open_q else '\u201d'); open_q = not open_q
        else: out.append(ch)
    open(path, 'w', encoding='utf-8').write(''.join(out))
```
检测与修复在字数脚本之前执行。**设定文档同规则**：细纲/规划表/档案/约束文档注入写作子代理前先做同一次半角引号成对替换（标点红线覆盖全部项目文档；子代理会照搬细纲直引号）；正文与设定文档同规则，均按本节执行。**替换后重扫确认**：成对替换在嵌套引号、奇数个引号、或引号出现在非对话语境时可能漏换——已观测首次替换后仍有 10 个半角引号残留。替换代码执行后立即 `content.count('"')` 重扫，>0 则对残留再次执行替换（通常一轮即可）。**

**全角弯引号方向配对（保存/修复后必检·与半角扫描同批执行）**：半角→全角只保证字符集，**方向**要单独验——句尾被打断处、对话穿插句收尾处易把收号误写为开号（已观测：一章末句 `上去把他撂倒——“` 的尾部开号应为收号，全章开/闭计数不符、逐行平差唯一病灶行即此句；首轮 U 与修复子自检都未发现，由二次复核拦下）。判法（脚本计数，不目测）：①全文 U+201C 数与 U+201D 数必须**相等**；②逐行比对开闭数，任一行开≠闭即病灶行。修法：定位行改方向（单字符机械替换，主代理可直接做，属 4.3 例外）→ 重跑 `text_guard digest` 刷新指纹 → 二次 U 复核确认无新 FAIL。修复子代理必须跑同一计数校验并在自检里报数（「中文标点全角、无混用」的自我描述不作证据）。

## 七、复核返修后同步口径（闭环后被返工时必执行）

返工改动正文后（U 意见修复、复核发现返修），改稿者必须同步下列口径，否则指纹/数字/证据包与正文脱节：

1. 重跑 `python scripts/text_guard.py -p [项目绝对路径] -c [章] digest` 刷新指纹；流水线内任何落盘改稿后都得重跑，以最终稿为准。
2. 新字数/段数/方差/指纹同步写入三处：`报告/第NNN章_章节档案.md`、U 报告「4.1d 六指标」节、`报告/第NNN章_朱雀证据包.md`——**段号锚点按最新正文段落号重核**（删段/改段后旧段号全部失效）。
3. `记忆系统/_state.json` 的**唯一写入方是 `state_commit`**——**不要**沿用「JSON 直改 + `state_render`」旧口径：字数变化走事务重开（`draft` → 只填 `delta.wordcounts["N"]` → `commit`；`--project` 按 cwd 相对解析、`--input` 传绝对路径），完整口径见 `references/写后流水线细则.md`「落盘改稿后必须重跑 state_commit」。
4. 终次复核报告命名「终版复核」（如 `报告/第NNN章_终版复核.md`）；【第NNN章状态】回执附终版指纹。已闭环的 `.done` 空标记语义不变、无需重标，只更新文档口径。

**复核返修（闭环后改动正文）再同步口径**：check-done 已闭环、`chapter.done` 已写后，复核子代理仍发现阻断项（如信息重复句须删）→ 修正文后：①重跑 `text_guard digest` 刷新指纹；②新字数/段数/方差/指纹写入 `报告/第NNN章_章节档案.md`、U 报告证据包节、`报告/第NNN章_朱雀证据包.md`（段号锚点须按新段落号重核——流水线内 4.1e 人工段注入与修复轮都会移动段号；旋正口径见 `modules/03_26_功能模块.md` 4.1e「段号旋正」）；③`wordcounts` 键为十进制数字字符串（如 `"15": 2725`）；**不要**沿用「`_state.json` JSON 直改 + `state_render`」这条口径——`_state.json` 的唯一写入方是 `state_commit`，流水线内任何落盘改稿（4.1e 注入段、修复轮、锚点补段）与闭环后返修**都**必须让 `wordcounts` 等于终稿口径：字数变化走事务重开：`python scripts/state_commit.py draft --project <书目录（项目根；其下是 记忆系统/_state.json，传其上一级会报「缺少 记忆系统/_state.json」）> --chapter N`（提交前先备份 `记忆系统/_state.json` 以便回滚） → 只填变化键（`{"wordcounts": {"N": 新汉字数}}`，按键级合并，不必重建整份 delta）→ `commit --chapter N --input .story/work/第NNN章/state.json`（提交成功即自动清理事务文件、revision 递增、派生件重渲染、`.done_state` 刷新）。**调用口径**：`--project` 按 cwd 相对解析（在项目父目录里传书目录名；传绝对路径会被再拼一层而报「项目目录不存在」）；`--input` 传**绝对路径**——相对路径按 cwd 解析，cwd 不在项目根时会报「事务文件缺失」。→ **commit 后派生件变更应仅 header `revision=` 递增**：sha256 前后比对应只见标记行变化、正文内容零漂移；出现内容级漂移即判异常（多为整替型字段只写了本章新值所致），用提交前的备份回滚并修正 delta 重跑，不带病继续。次序见 `references/写后流水线细则.md`「落盘改稿后必须重跑 state_commit」；`scripts/state_render.py --project <项目绝对路径>` 只用于单独重渲染派生件（参数名是 `--project`，非 `-p`）；④终次复核报告命名『终版复核』并在【第NNN章状态】回执附终版指纹。**复核范围分级（每轮改稿对应一次复核，勿每轮全量重审）**：
- **机械级**：单字符/标点方向、段落机械拆并、纯格式改动（<5% 正文字数）→ 窄范围「收尾复核」：①贴修复后原文逐字比对被改点；②机械核验重跑（字数脚本、引号方向配对＝U+201C/U+201D 计数 + 逐行平差、段落/句数脚本、状态台账核验）；③上一份复核的八节结论逐条写「沿用」，仅对与本次改动直接相关的节重审；④反向扫新（本次改动是否引入断句/标点混用/对话标签断裂，无则写「无」）；⑤报告命名「收尾复核」、末行三态（PASS/FAIL）；是闭环前最后一次复核时，同步引用进合并报告并附终版指纹。
- **内容级**：措辞、人设、对话风格、多段联动、新信息 → 必须全量八节复核（03_26 4.3 修复路径），不得降级为收尾复核。
- 迭代修复中本轮复核又发现新问题 → 只修该问题对应项后再复核一次（范围按上表分级）；禁止每轮重审整章，也禁止跳过复核直接写 `.done_chapter`。
勿把重复稿直接送进流水线。

**复核必须重跑客观计量项（文字自评不作数）**：每轮复核除八节文字结论外须重跑客观量并报数——引号开闭计数与逐行平差、CJK 字数/段数/句数/句长方差、`text_guard digest` 指纹。首轮 U 与修复子代理都在语文层面判通过、客观配对缺陷（弯引号方向错配）仍在正文，由下一轮的客观量拦下——「标点全角、无混用」的文字描述不作证据。客观读数必须落在**当前正文**上：任何注入/修复/返修之前先跑一遍留「基线」读数，此后每轮改稿重跑终值，报告把基线与终值并列写（判据落旧稿口径、或交叉比对两个脚本的方差，都会得出与正文不符的结论）。**句数与对话占比同样有口径，跨代理数值差异先按同口径重算再判**：句数有两种切法（按句末标点切分全文 vs 按折行计句），同章可差 25–35%（实测 511 句 vs 380 句）；对话占比有三种口径（引号内字符／含对话句／对话行数），同章差 10 点以上甚至方向相反（实测字符 38.4%／行数 49.0%／另一口径 29.7%）。两代理数值对不上**既不判 AI 特征、也不判数据失准**——固定一套主口径（优先与 check-done 一致）重算，两套值并列记进报告并各注口径来源，达标判定只认主口径，其余口径只作旁证。同一指标的不同口径禁止混用判达标：报告引用任何比例须带口径标注；某口径未达标而强行达标需净增 ≈N 字时，先按用户字数硬上限核算——触限则**让位**（写明让了哪条指标、代价是什么、依据＝哪条用户硬约束优先级更高），并在报告「口径更正」节、章节档案、规划表本章行或执行点所在行、【第NNN章状态】回执四处登记**遗留执行点**（下一章/预算章的收敛方向），不算本章 FAIL。复核子代理指出报告读数不可复现时，须按其口径重算后更正原读数、写「更正登记」，**严禁保留不可复现的读数**。判方差口径只认一个脚本（默认 `scripts/fingerprint.py`，UTF-16 单元含标点）；子代理自报读数只作旁证，且须与脚本口径对齐——同一章实测两口径可差几十点，混用即翻转 `≥110/90–110/<90` 判定。`text_guard digest` 的输出里 `sha256=` 是**缩写小写十六进制，长度不固定**（按 `[0-9a-f]{6,64}` 解析，勿按固定位数写死——已观测按 16 位解析读不到），另一标识记 `单元=`（= `fingerprint.py` 的「总字数」口径，即含标点字符数）；指纹以 `单元=` 的值是否进入 `.story/text-digests.json` 为准。


## 八、待定事项（提案·未启用·未经作者确认不得作为门禁执行）

> 本节仅记录待评审设计，不属于现行门禁/流程。

- **输入侧保真缺口**：写入侧有硬门禁（check-done P0–P6），读取侧无钩子——写作/改大纲/更新角色数据前须读的档案，若子代理未读而凭印象写，设定漂移不可见。
- **候选方案（提案）**：交付物附「读取证明」JSON：每份被读文件声明 `sha256` + 从该文件原文提取的连续子串 `extracts`（≥3 份文件、每条 ≥6 汉字、容忍少量标点差异）+ `read_at` 早于正文 mtime。校验脚本交叉验证（现值哈希一致 + extracts 确为原文连续子串）——幻觉抽取几乎不可能连续命中原文，可显著拦截「没读就凭感觉写」。可并入 check-done 规则集增补 P7 门禁；未实施。
