# ADR：同类项目机制移植的收敛纪律

- 状态：accepted
- 类别：机制移植
- 日期：2026-10-15

## problem

GitHub 同类项目（oh-story / webnovel-writer / inkos / ANWA / OpenFic / MuMu）各有一套有效机制，直接搬运会带入外部依赖与重复资产；缺少收敛口径时移植变成抄袭拼盘，且无法验收。

## decision

1. 19+4 项编号清单（P0–P3；P3-20 用户决定移除、P3-21~24 对账补录）+ 每项「来源证据 / 落点 / 验收」三段式；标 `[收敛]`（≥2 项目独立实现）者优先。
2. 双实现纪律：py 为权威、ps1 为兜底，输出**逐字节一致**，回归对拍入 `test-check-done.py`。
3. 三道门禁全绿才提交：回归 + `audit.ps1` 全开关 + `check-doc-budget`；进度回填执行清单/状态表/实施记录。
4. 外部资产只引证据不引运行时（如 `deslop-lexicon` 是 OpenFic 资产，不可引用；**例外：2026-10-18 用户显式授权 deslop 体系移植**，出处随文保留，见实施记录 §三.15a）。

## validation

- PR #6 十余 commit，CI（audit.yml）success
- 回归 54 → 104（+12 任务书 +8 detect +10 guard +20 state 等双实现对拍；时点值，终态 410/410 见实施记录）
- 偏离项全部记录于实施记录（预算 45K→…→48,500→49,500 沿革（完整链见 doc-budget.json path_ceiling.why）、migrate 双张力、schema 补字段等），无静默偏离
