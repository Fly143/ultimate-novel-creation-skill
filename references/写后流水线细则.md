## 4.1b `--stop-at-dashes` 的污染原理

第 1/2/4 项实现（`fingerprint.py` / `.pl` / `.ps1`）**不支持** `--stop-at-dashes`，只有 `fingerprint.byte.pl` 与 `wordfreq.byte.pl` 支持。正文末尾带 `----` 元数据块 + YAML 的章节：用前三项会把元数据当正文统计，句长方差/段落数/对话占比全被污染，而修复子代理正是按这些数值"改分布"，等于把修复导向错误方向。正文末尾无该块的章节无需该旗标。

## 分布"防过度"的完整口径

- 拉大方差靠**长短自然交替**：长句内部加逗号节奏、关键处用短句强调。
- **禁止**把长句机械切成碎片凑方差；**短句连篇**（方差反而很低）也勿强拉长句。
- 修复后通读改动段落：出现"碎句堆砌 / 一句一段 / 读起来断断续续" → 优先回退为长句微调，而不是继续切短。
- 分布区间是"像不像人"的参考，**不是牺牲通顺的硬指标**：通顺与方差冲突时通顺优先，报告注明 `note: distribution relaxed for readability`。

## state_commit delta 事务文件字段格式（完整自查清单）

`draft` 生成空事务 JSON 后，填 `delta` 时**必须**满足以下格式要求。每条不满足都会在 `commit` 阶段才报错（不在构造时静默通过），反复 read-modify-retry 浪费 5–10 分钟。填完后逐项自查再提交。

### context.position 须为对象

`delta.context.position` **必须是对象**，不能是字符串。正确格式：
```json
"position": {
  "city": "临江市",
  "location": "异能学院训练场",
  "chapter": "第7章"
}
```
写成 `"position": "第7章"` 触发 `delta.context.position 须为对象`。

### `summaries` / `wordcounts` 键须为十进制数字字符串

`delta.summaries` 和 `delta.wordcounts` 的**键**必须是纯数字字符串（`"7"`），**不能**用 `"第7章"` / `"第007章"`。写错触发 `summaries 键必须是十进制数字字符串（≤18 位）`。

### foreshadow 条目须为对象

`delta.foreshadow` 的**每个值**必须是对象（含 `desc` / `status` 字段），不能是字符串。写错触发 `foreshadow.XXX 须为对象`。同时，条目内部的 `planted_ch` / `planned_resolve_ch` / `resolved_ch` **必须写整数**（`1`、`0`），不可写字符串（`"1"`）——会触发 `TypeError: '<' not supported between str and int`。

```json
"foreshadow": {
  "烧穿风险": {
    "desc": "攒满自爆型，断则烧穿不可逆",
    "status": "active",
    "planted_ch": 7,
    "resolved_ch": 0
  }
}
```

### facts 条目须为对象

`delta.facts` 的**每个元素**必须是 `{fact, category}` 对象，不能是裸字符串。写错触发 `facts 条目须为对象` 或合并校验失败。

```json
"facts": [
  {"fact": "唐晓棠的线从心口到指尖约70公分", "category": "bug细节"}
]
```

### draft → fill → commit 工作流

1. `python scripts/state_commit.py draft --project "[路径]" --chapter N` — 生成空事务模板到 `.story/work/第NNN章/state.json`
2. 读取模板，填写 `delta` 所有字段（按上述格式要求）
3. `python scripts/state_commit.py commit --project "[路径]" --chapter N --input ".story/work/第NNN章/state.json"` — 提交事务

### 项目侧脚本的 `--project` 与 cwd 拼接口径

`text_guard.py` / `state_commit.py` / `state_render.py` / `read_proof.py` 都按「`--project` 值 + cwd 拼成本书目录」找文件，两种合法形态**不可混用**：

- ① cwd = 书目录的**上一级** && `--project` = **书目录名（书名）**；② `--project` = **书目录绝对路径**（cwd 无关）。
- 混用（cwd 已在书目录内 + `--project` 又传相对书目录名）→ 拼出「书目录/书目录」双层路径 → `rc=2【文本指纹】第016 正文文件未找到（glob：正文/第016章_*.txt）`。这不是缺文件，是路径形态问题：换一种形态重跑即过，不要建副本或改文件布局。
- 同族例外：`read_proof` / `check-done` 的 `-Proof` 抗体传**相对路径**（传绝对路径会让绑定失败）；其余项目侧脚本传相对名或绝对路径皆可。

### timeline / characters / overview 结构

- `timeline` 为对象：`readers_known` 和 `authors_truth` 均为字符串数组
- `characters` 为对象：每个角色为 `{change, status}` 对象
- `overview` 为对象：含 `stage` / `progress` / `chapter_count` 字段

**标点红线覆盖派生件（delta 文案一律中文弯引号）**：主代理写入 delta 或总结文案的引号会被 `state_render` 原样透传——在 delta 里用直引号会让摘要/事实台账/伏笔清单/上下文卡渲染出半角引号，污染「无半角引号」检查。delta/报告文案一律中文弯引号；半角引号扫描范围＝正文＋派生件（渲染后的产物）。派生件检出半角引号 → 改源头 delta 重跑 `state_render` 与 `commit`（禁手改派生件），再决定是否重跑 U/复核。正文层无半角≠派生件干净。

**delta 合并语义与提交纪律（已观测报错）**：①**合并语义是整替不是追加**：delta 对 `characters.known_facts` / `foreshadow` 各字段 / `overview.snapshot.key_facts` / `overview` 各键 / `context` 是「以 delta 为准整体替换」——只写本章新增会**静默丢掉**既有条目（不报错，渲染出来就是空的/缺的），写前必须把旧值与新增并排写全量；只有 `facts` 与 `timeline.readers_known|authors_truth` 是按章替换、逐条去重的追加。`draft` 产出的事务 JSON 骨架＝`{chapter, expected_state_revision, mode, _hint, delta}`，**变化字段一律写在 `delta` 下**（字数＝`delta.wordcounts["N"]`，只填本章变化键；写成顶层 `wordcounts` 会被 `commit` 无视）。构造完 delta 自问一句：「被我整替掉的字段里，有没有只存在于 state、没写进 delta 的旧条目？」**②`facts` 里的 `chapter` 字段须为十进制整数**（`19`，不是 `"19"`）——写成字符串会报 facts 键类型错、须改事务重跑；修字段时注意事务 JSON 的缩进带空格（`"chapter": "19"`），按无空格子串匹配会静默零命中，改用正则 `"chapter":\s*"19"` → `"chapter": 19` 再提交（Python 里用原始字符串字面量）。③**`delta.characters.<角色名>` 的值必须是对象**（含 `snapshot`/`aliases`/`known_facts` 子键，如 `{"snapshot": "…"}`），写成字符串报 `❌ delta.characters.X 须为对象`；角色快照属整替语义，「本章追加」须把旧值与新值拼成完整字符串再写入，只填新值＝把历史快照整个换掉。④**改事务 JSON 字段后必须先落盘再调 commit**：只改内存对象、忘记 `json.dump` 写回事务文件时，commit 仍按盘上旧 delta 报同一个类型错（连续两轮才生效）——每改一批字段即写回一次事务文件。

## 写作子代理后校验：ASCII引号·UI文本·禁用词·段落句长·时间指代

写作子代理常无视"必须用中文弯引号"的指令，返回的正文里混入 ASCII 双引号（`"`）。同理，文风设定中的"每段最长不超过N句"约束、去AI化禁用词规则也可能被忽略，甚至出现游戏UI风格文本，且默认用"昨天"指代过去事件（不知故事中"今天"是第几天）。03_06 步骤4 保存正文后应增加五项机械校验，命中后**批量替换/定点拆段/定点改写**，不退回子代理（机械操作比重写快且安全）：

1. **ASCII 引号扫描**：`python -c "import sys; t=open(sys.argv[1],encoding='utf-8').read(); n=t.count('"'); print(f'ASCII双引号:{n}个')" "正文文件路径"`。命中 >0 → 按开闭替换为中文弯引号（`"` → `“`/`”`，`'` → `‘`/`’`），重新保存。
2. **段落句长上限核对**：若文风设定「每段上限句数」字段有具体数值（>0），保存后逐段统计句数（按句末标点 `。！？` 切分），标记超限段落 → 退回子代理**定点拆段**（指明第几段、当前句数、目标上限），禁止全文重写。
3. **游戏UI文本扫描**：保存正文后扫描 `【` / `】` 字符，命中即定位并改写为角色内心感知/叙述性描写（保持原信息量，仅换表达形式，如 `【已使用：一】` → `第一格，灭了。`；已观测还有 `【检测到异常：循环计数型】`、`【机制：每释放七次，中断一次】` 等系统通知式文本——非小说叙事文体，严重破坏代入感并**触发朱雀 n-gram 模板指纹**）。此检查与 ASCII 引号扫描同批执行。
4. **一级禁用词扫描**：wordfreq 脚本输出的 ❌ 高危词命中即替换（瞬间→那一刻/当时、然而→但/结果、深吸一口气→直接删或改角色动作）。此检查与 wordfreq 脚本同批执行。
5. **时间指代词扫描**：写作子代理不知故事中"今天"是第几天，默认用"昨天"指代过去事件，高频与已确立时间线矛盾（已观测：第8章"昨天"×7全部与"第4天下午"矛盾，其中3处事件前7章无出处，1处与第6章实测直接冲突）。扫描 `昨天/前天`，逐处核对 `记忆系统/上下文.md` 的当前章节位置——时间指代错误 → 改为正确的故事日参考（"中午""上次""之前"）；该时间指代的事件在前文无出处 → 改为模糊指代（"上次""之前"）或删去。此检查与 ASCII 引号扫描同批执行。

这五项与人工种子核对（步骤4 第7条）并列，均不省略。

> **修复/强化轮同样适用**：4.3 修复子代理与 4.1e 强化轮改稿后可能引入新的半角引号。改稿交付后必须重跑 ASCII 引号扫描，命中>0 → 批量替换为全角弯引号，再进入下一步。此检查与 `text_guard digest` 同批执行，不额外占用独立步骤。

## 修复优先级：改最少原则的具体化（防「全改」与「全不改」两个极端）

> 本条澄清 03_26 步骤4.3「全量修改所有标记」与同模块「改最少原则/防过度」的张力；03_26 正文应同步修订为按本条分级（此处为设计说明，动作权威仍在 03_26）。

U 分级返回时按等级取**最小必要改动集**：

- ❌ FAIL（逻辑硬伤/跨章矛盾/OOC/因果断层/设定矛盾）必修。
- 🟡 低优建议项**评估后部分可不改**，须在报告修复记录注明理由。可不改的典型：①合规压线（环境描写压线句数上限但毛边细节到位、句长方差偏低但属短句流文体特征）②核心爽点故意留白（智斗翻盘不交代战力机制、章末悬念故意不闭环）③改动会破坏 prose 性格或引入 AI 腔。

改最少 = 「必修项全修 + 建议项按影响评估取最小集」，非「全改」也非「全不改」。跳过项必须在报告修复记录写明理由（哪条、为何可不改），供用户复核。

**流程边界**：本流程（U 审核修复）的「改最少」与独立子代理审计的「全量修🔴🟠🟡🟢四级」是两条独立流程，不互相套用——审计铁律要求全量修四级属另一质量门禁，不因 U 审核修复跳过低优建议项而违反审计铁律，也不因此放松 U 审核修复的必修项。

## 落盘改稿后必须重跑 state_commit（终稿字数同步）

4.1e 强化轮（人工段注入）、4.3 修复轮、机械补时间锚点等**任何**落盘改稿都可能改变正文字数——字数一变，`_state.json` 里的 `wordcounts` 就会停在旧值。改稿交付后必须按序重跑：

1. `python scripts/text_guard.py digest --project <书目录名> --chapter N` — 刷新指纹为最终稿（cwd＝书目录上一级；只给 `--chapter` 时正文找不到，参数形态同 03_26 五）
2. 重开事务并提交新字数（上一份事务已提交成功即被脚本删除，必须重新起草；合并是**按键级**的，不是章节级）
   - `python scripts/state_commit.py draft --project <书目录名> --chapter N` → `delta` **只填变化键**即可，例如 `{"wordcounts": {"N": 新汉字数}}`（已实测：仅此键即可提交成功，其余键沿用 state 既有值；结果＝派生件仅头部 revision 标记刷新，正文内容零漂移）
   - `python scripts/state_commit.py commit --project <书目录名> --chapter N --input .story/work/第NNN章/state.json` → 事务提交：自动清理事务文件、revision 递增、24 个派生件重渲染、`.done/第NNN章_state.done` 刷新
   - 仅当本次还要同时补伏笔/事实/时间线时才重建整份 delta（重建口径：「整替不是追加」）
3. `check-done` — 复核闭环标记仍全齐
4. 若章节档案/规划表执行注/报告已落盘而字数继续变化，同轮把其中所有「本章字数」按新值改掉（口径＝汉字数，见 `modules/03_06_功能模块.md` 步骤4「子代理回传验证」⑤）

若跳过第2步，`.done` 标记仍在但字数与正文不符，后续跨章一致性检查会误报。此步骤在「更新报告后再向用户汇报」之前执行。

## 周期长文档（阶段压缩/参数链/卷压缩）的合成纪律与内容骨架

> 触发：每10章（阶段压缩＋参数链＋创新评估＝`report/创新深度检查报告.md` 一节）、每50章（卷压缩＋卷参数快照）。`check-done` 文件闸只判存在且非空（`phase_compress` / `file_gates`），内容构成由本条负责。

### 合成纪律（禁走日志转写）

阶段压缩/参数链属上千字长文档。子代理回复正文里的长文本会被日志按行截断并尾附 transcript（形如「…(+N chars)」），主代理据日志转写必缺段缺字，且本会话已实测一次（日志分节文本落盘后缺漏，返工改用会话文本精抄）。因此：

1. **子代理直接写盘**：合成任务书写明目标绝对路径，让子代理把产物写进 `记忆系统/阶段/`（或 `记忆系统/卷/`），回传路径 + sha256 + 各节字数；主代理只做口径/字数/小标题齐全核验。
2. **必须主代理自写时**：按下方骨架**逐节从会话文本精抄**，落盘后核对小标题齐全 + 总字数落区间，**勿把日志里的分节文本当全文源**。
3. **写前先比对温度**：`write_file` 对已存在路径会拒写（`Refusing to overwrite`）——同一批 tasks 可能已由前序步骤落过同名残留文件，落盘前先查存在性，已存在则 `rm -f` 再写（命令经 terminal 执行）。

### 落点公式

- 阶段压缩：`记忆系统/阶段/阶段{n}_第{start}-{end}章.md`，**n＝本章章号 ÷ 10 取整**（第10章→`阶段1_第1-10章.md`，第20章→`阶段2_第11-20章.md`）
- 参数链：`记忆系统/阶段/阶段{n}_参数.md`（每10章一份）
- 卷压缩：`记忆系统/卷/卷{n}_第{start}-{end}章.md` + `记忆系统/卷/卷{n}_参数.md`（每50章，n＝章号 ÷ 50 取整）
- 创新深度评估：**追加**到 `报告/创新深度检查报告.md`（同一文件复用，新增「检查范围：第{start}-{end}章（第{n}阶段）」小节并加小节结论）

### 内容骨架

**阶段压缩**（7 节，照写不改写）：`## 阶段标题` → `## 一句话概括` → `## 剧情推进`（表格列＝关键词／变化；行＝开场状态·核心冲突·关键转折·结局状态）→ `## 人物线变化`（各人「进入本阶段时 → 离开本阶段时」）→ `## 本阶段未回收伏笔清单`（`- [ ]`，按伏笔清单抄）→ `## 读者须知`（5–7 条客观信息）→ `## 存档说明`（版本与用途）。

**参数链**（`阶段{n}_参数.md`）：五段结构置于 ```` ```text ```` 围栏——`[1. 时空常量锚点]`（本章锚定的绝对时间/天数）｜`[2. 主角状态]`｜`[3. 力量体系与资源池]`｜`[4. 空间与情报拓扑]`｜`[5. 剧情因果锁]`。

**读源**：阶段压缩与参数链读**各章档案「参数链条」节**（03_26 步骤6 产出，五区块结构），**不回读正文**（正文是长流程，档案是唯一权威汇总）。

### 与既有文档的关系

创新深度检查结论「达标／需改进」同时是阶段压缩的可选附录；本条只定义合成方式与骨架，四维度评分与子代理调用规格仍归 `modules/03_14_功能模块.md`。
