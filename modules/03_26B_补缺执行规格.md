# 补缺执行规格（03_26 附属·按需读取）

> **归属**：本文件是 `modules/03_26_功能模块.md`「补缺」流程的★状态读取侧权威定义，随 03_26 拆分独立成文（按需加载：仅「补缺」触发时读取，写一章热路径不再常载）。
> **触发**：用户说「补缺」、写后命令表「补缺」、或 00 协议兜底规则；「缺什么」永远由 `.done` 目录推导。


> 触发：用户说「补缺」、写后命令表「补缺」、或 00 协议兜底规则（用户指出漏步 / `.done` 检测到断裂 / 跨会话时 `.done` 不完整）。一句话原则：**「缺什么」永远由 `.done` 目录推导，不由任何正文或档案文件推导。**
> 可选客观核验：`scripts/check-done.ps1` / `scripts/check-done.py`（规则单源 `scripts/check-done-rules.json`），按项目目录+章节号核验必需标记（章号兼容 `第NNN章`/`第N章`）。**只认 `.done` 空标记 size=0，非空判无效。默认要求 `chapter.done`。** 报告「人工证据包」节**默认硬校验**：标题 + 结构证据类别 ≥2 类且至少含一类强证据，须带段号/字数结构 + 正文段号交叉。`--soft-report`/`-SoftReport` 与 `--no-chapter-done`/`-NoChapterDone` 仅调试。不代替补跑。**禁止**使用 `--allow-non-empty`/`-AllowNonEmpty`。写后闭环建议带 **`--require-task-sheet`/`-RequireTaskSheet`**（细纲任务书四段 + `（必落）` 拍全勾，缺则 exit1）。对外汇报必须分列流水线结果与朱雀三态/待检测。

```
步骤1：定位当前章
  → 读项目根 .active-book 定位当前书 → 取最新一章 N（正文/ 下最大编号）
    用户显式指定章号时以用户指定为准（如「补缺第12章」）

步骤2：读取权威状态（唯一来源 = .done 目录）
  → 列出 [书名]/.done/ 下所有「第NNN章_*.done」空标记
  → 与第七节「必需标记」清单逐项比对（按章号判断是否含 innovation）
  → 得出：已完成集合 / 缺失集合
  ⚠️ 禁止从 报告/第NNN章_章节档案.md 的元数据推断完成步骤——该文件无「完成步骤」字段，
     且空标记（.done）不是空值状态，两者不可互相替代

步骤3：归一化档案文件（幂等）
  → 按本章 .done 实际结果重出 报告/第NNN章_章节档案.md（编号三位补零，与正文命名一致，避免与既有档案并存）：
     · 已存在 → 按实际完成情况修正「字符数/审核评分/审核时间」与 YAML 参数链条节
     · 不存在 → 生成（缺 YAML 时按 03_24 模板从本章正文 + 圣经补填）
  → 本步骤只对「档案文件」做归一，不伪造任何 .done 标记

步骤4：按缺失集合补执行
  → 缺失步骤按「一、总流程」步骤1-5 的顺序逐个补跑（该调子代理的仍调子代理，该主代理做的仍主代理做）
  → **缺 zhuque → 必须补跑 4.1b–4.1e 人工证据包并写 `.done_zhuque`**（delegate 失败时主代理降级自审仍不得省略）
  → 步骤6 章节档案不落 .done，不在本步骤补跑（由本规格步骤3 归一）
  → 每补完一步，立即写对应 .done 空文件

步骤5：闭环确认
  → 必需标记齐备 → 写 .done_chapter（若缺失）
  → 输出简报：补了哪几步 / 仍缺哪几步 / 是否闭环
```

**铁律**：
- 缺失判定只认 `.done` 空标记；**不存在"从文件内容推断完成步骤"的旁路**
- 补执行不得重写已完成步骤的产物（如圣经、摘要已更新则不重复更新，除非用户显式要求「重写第N章」）
- 若某步骤的产物存在但标记缺失 → 视为「未完成」补跑该步骤并补标（宁可重跑，不可凭产物内容推断已通过）
- 补缺后档案文件与 `.done` 一致；若历史项目的**旧正文明细**里含旧版「完成步骤」字段，可直接忽略该字段（已废除；该字段只可能存在于 v9.5.18 之前的正文末尾，档案文件自 v9.5.18 起才存在且不含此字段）
